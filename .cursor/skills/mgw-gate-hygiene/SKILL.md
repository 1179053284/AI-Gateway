# 验收门卫生与报红归因（Model-Gateway）

## 0. 边界与前置

- **谁跑门**：`mgw-delivery-round` 第 3 步（命令字面在 `.cursor/memory/runbook.md` §3）。本支只在**改门 / 加判据 / 门报红要归因**时加载。
- 开工必读：`.cursor/memory/pitfalls.md` 前端/门相关条目（`P-015/P-030/P-033/P-044/P-046/P-048-P-049` 是本支所有教训的**唯一正文**，本支只给操作顺序，不复制；编号引用，不引行号）。
- 先分清「是不是我造成的」：并行会话在飞时，`git show HEAD:<file>` 跑同一套抽取判断是既有缺陷还是本轮引入（别背别人的红，也别把既有缺陷当本轮）。

## 1. 三门的终局行（只认门自己那行）

| 门 | 终局行字面 | 备注 |
|---|---|---|
| 账号静态门 `verify_accounts_ui.mjs` | `合计：N 通过 / M 失败`；变异：`可红 X/Y；Y 条判据全部可证伪（expectGreen 型…）` 或 `…；N 项 BAD` | 红时失败清单打在合计行**之后** ⇒ 取数 `grep` 不 `tail` |
| v2 前端门 `verify_v2_frontend.mjs` | `实测 N 项，通过 N 项，失败 0 项` | 裸调 = 打印用法并 exit 2，必须吃 `make_overview_payload.py` 的载荷 |
| 真机门 `verify_accounts_ui_live.py` | `合计：N 通过 / M 失败` | 退出码 0/1/2（2 = 运行事故，不是判据红） |
| 回执门 / 参数卡门 | 各自 `合计：…` | `--mutate N` 要求**逐条恰一红** |

报告里的数字**只抄运行器自己那行**，不手推、不四舍五入、不"约等于"。

## 2. 改门后的三步自检（顺序执行，缺一步都算没改完）

1. **内嵌 JS 语法**：`python3 <本 skill>/scripts/check_gate_js.py bianyiandhuanjing/scripts/verify_accounts_ui_live.py bianyiandhuanjing/scripts/verify_settings_layout.py`
   - 它按 runner 同姿势（`= r'''…'''` 边界 + 4 个占位符裸路径替换）抽出 JS 写 `.mjs` 再 `node --check`；
   - 取不到块 ⇒ **rc=2 点名报红**（绝不静默通过）；任一块语法坏 ⇒ rc=1 且点名行号范围。
   - 实测基线（2026-10-07）：`verify_accounts_ui_live.py:615-2831`（2216 行）与 `verify_settings_layout.py:39-418`（379 行）双绿；负例（`/tmp` 副本多打一个 `(`）rc=1；空文件 rc=2。
   - 🔴 直接 `node --check x.js` 按 CommonJS 解析 = 假绿，**不要**用它替代本步。
2. **Python 侧语法**：`python3.12 -m py_compile <改过的门>`（含 walrus/f-string 的脚本系统 3.9.6 会崩，用 3.12）。
3. **真跑一轮再判红**：语法 ≠ 渲染。改完先跑**最小探针**（新起页 → goto → evaluate 标题）确认浏览器通道可用，再跑整门；中途 **kill 在跑的门会毒化下一轮标签页**（`page label not found: pN` 连片 FATAL）。

## 3. 新增判据前的两项预检（先查后写，防假通过与吞行）

1. **判据 id 全局唯一**：`grep -o 'ck("[A-Za-z0-9]*"' bianyiandhuanjing/scripts/verify_accounts_ui_live.py | sort | uniq -d`
   - 同号会被报告**静默吞行**（后写覆盖先写，输出里根本不出现）；
   - 🔴 现状已登记 4 个重复：`D6a` `D6b` `MS2f` `MS8`（2026-10-07 实测）——新判据**不得**再撞；这 4 个属门侧既有缺陷，报备不代改。
2. **变异锚点命中恰 1 次**：新写的代码里不得复用既有锚点原文（曾把 V4 锚 `const rq = a.runtime && a.runtime.quota;` 撞成 2 次 ⇒ 门报 BAD）；改锚后**必须复跑 `--mutation` 看命中数**——"没报错"不等于锚点生效；锚文本少一颗反引号就会命中 0 次报 BAD。
3. **判据必须有对象**：先去 fixture/种子/真机数据里确认"那个形状真的会渲染出来"。空的判据（聚合后单组 ⇒ chips 行从不渲染、`models: []` 的实例 ⇒ 无行可断言）是**恒绿的空过**；要么补种子造对象，要么让判据自己造对象再归零。

## 4. 门报红五分类归因（逐条读门的 `｜实测` 读数再分类）

| 类 | 症状 | 确认动作 | 处方 |
|---|---|---|---|
| **A 实现缺陷** | 读数与预期真不同 | 复跑一次；必要时最小探针复现 | 修产品代码；布局类判据**成对**（对齐 + 不溢出），只验一侧等于给自己发通行证 |
| **B 判据读点搬家** | 界面上东西还在，判据恒空/恒假 | 对比"判据读的点"与"实现写进 DOM 的点" | 判据读点=用户看得见的那个节点（悬停证据挂**格根**，不挂内部 span）|
| **C 判据空转（没有对象）** | 恒绿 | 查 fixture 是否真渲染出那个形状 | 补种子/自造对象；改完复跑确认它**能红** |
| **D 判据假红/结构性不可能绿** | 恒红或永远不红 | 读判据谓词**全部**分支（含 helper 的第三条正则）；把断言打在拼接串上=结构性不可能绿 | 改写谓词；负向扫描先剥注释；扫描面先问"这段文本为什么会在场"（`<script>` 内容/title/隐藏节点都算在场） |
| **E 过期红（新增类）** | 判据对象已不存在、跨 ≥2 轮只被归因不修 | 查该红最早出现轮次 + 判据钉的东西是否已被推翻 | **>1 轮必须改写或删除判据对象**，不许长期挂"合法红"——`190/1` 与 `190/0` 不可分辨等于门失效（`SEC-renew`/`E12` 实例：`docs/changes/reviews/arch-audit-20261005/R5-verification.md:40,53`）|

归因工具链（复现不出时按序上）：
`stripComments` 失步要**抽门自己的 helper 到 Node 里 eval**（别重写近似实现）→ 冻结树到 `/tmp`（副本必须放在与门脚本**相同的相对位置**，ROOT 由脚本路径推导）→ 门的一份带调试输出的临时副本（打印命中上下文，用完即删）→ `git show HEAD:<file>` 判既有/本轮。

## 5. 撤证配方（🔴 唯一主人：delivery-round / panel-verdict 一律引用本段，不许各写各的）

1. 一次只回退一条，**不打包**；不改动范围外的行。
2. 等长替换（`max(`→`min(`）必须**清 `__pycache__`** 或改长度——`.pyc` 的 (mtime,size) 校验位会让"复原了还红"。
3. 撤证与全量 pytest / 门**串行独占**，绝不并发（并发制造与代码无关的幽灵红）。
4. 红证要**点名失败的判据 id / 用例名**，只报计数不算证据（一轮三次回退计数长得一样）。
5. 复原后：md5 与动手前逐字节一致 + 回全量绿；台账撤证行**如实写本次实跑的文件集范围**（2 文件红不许写成 7 文件）。
6. 复原一律用 `/tmp` 备份或按行 inverse edit；**禁** `git stash` / `git checkout --`（会抹掉自己或并行会话未提交的改动）。
7. 变异只改**语法**不改结构：变异里引用未定义变量会让假 DOM 整体崩掉，红来自"整页没渲染"= 无效撤证。

## 6. 判据随设计前进（设计变了，判据不许消失）

- 旧判据**反转改写而不是删条目**（条数不减）；理由（日期 + 用户原话 + 推翻原因）写进判据注释。
- 换载体（按钮→开关、tooltip→常驻行）⇒ 重定锚 + 把断言改到新载体上，并给新形态补一条**能打死它的变异**。
- 判据写"这次改动改变了什么"，不写"我以为会发哪几个请求"（后者被同表其它合法行打穿）。
- `expectGreen` 型判据（基线为绿、靠变异证伪）必须计入可红分母；基线上就是红的判据**不可核验**，要显式记 skipped 而不是算通过。

## 7. 拆分 / 重构类改动的专项（10-06 三次 P0 的机械兜底）

1. **import/export 契约**：`python3 <本 skill>/scripts/check_esm_symbols.py`
   - 腿①：每条相对 import 的目标文件必须在盘上（10-06 P0#1：`../api.js` 应为 `../../api.js` ⇒ 全站无渲染，而 vm 静态门看不见这层）；
   - 腿②：具名 import 必须 ∈ 目标的导出集合（同日前两次 P0：主文件没 export / 子模块 import 不存在的名字）。
   - 实测基线（2026-10-07）：现树 `16 通过 / 0 失败`；负例两条各恰一红（目标不存在 / 符号未导出，行号对得上源文件）。
2. 🔴 **本脚本不提供的**：跨模块"未定义引用"扫描。10-07 实测三种启发式全被正则字面量/模板串打成大面积误报（恒红的检查器 = 没有检查器）⇒ 该腿的权威做法是**运行期**：逐模块 `node --input-type=module -e "import('file:///…')"` + **真浏览器逐页渲染**（8 页一页不能少）。静态契约绿 ≠ 页面能渲染。
3. 拆分验收的完整判据 = 静态契约（本脚本）+ 运行期逐模块 import + 真浏览器逐页 + 弹窗级实测（`fmtTok` 那次只炸一个弹窗）。

## 8. 收敛口径

- 终局 = 门自己那行的 0 失败 + 变异满额且 `0 项 BAD` + 撤证成对 + md5 吻合 + `SHIP-GATE: GREEN`（含后端改动还要"已重启"这一条，见 delivery-round §7）。
- **不许**为了绿而：放宽阈值、删判据、把样本缺失判通过、改数字蒙绿、用 `--skip-legs` 充当交付。
- 同一颗红第 2 轮仍未收敛 ⇒ 停手升层（规矩 8），书面写清"卡在哪一步、已试什么、下一步换什么层"。

## 9. 红线

- 改门 = 改判据的**能力**，必须配撤证；只改文案/注释不算改门。
- 共享树：别在门跑到一半时改源文件（该轮读数作废）；改完立刻 `check_gate_js.py` + `py_compile`。
- 临时件（冻结树、`.mjs`、调试副本）一律 `/tmp`，跑完清理（规矩 12）。
