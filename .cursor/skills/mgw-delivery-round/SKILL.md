# Model-Gateway 一轮改动 → 交付

## 0. 先判定：这一轮值不值得走全环（防与 mg-10 快路径打架）

**走本环**：有交付语义的改动 —— 跨层/多文件、UI 改版、契约或配置语义变化、用户点名「验收 / 复验 / 充分核验 / 合并 main」。
**不走本环（退回 `.cursor/rules/mg-10-methodology.mdc` 快路径）**：单点小修 / 单点样式 / 单文件一行 —— 取证三选一 → 只改目标文件 → 单点验证 → `pitfalls.md` 补一行，**不加 todolist、不逐条等人工验收**。
**也不走本环**：任务分支上积压的多个 commit 批量验收合并 → `batch-acceptance-merge`；纯调研/给方案 → 直接写文档，别跑门。

命令字面**不在本文件**：全部在 `.cursor/memory/runbook.md`（§1 环境 / §2 运行 / §3 验收门链 / §4 数据位置 / §5 授权）。本文件只写**顺序、判读与停手点**。

## 1. 开工基线（动代码之前）

1. `git status` + `git log --oneline -5`：认领改动面；看是否有**并行会话**在飞（未提交集、文件 mtime、`git diff --numstat HEAD -- <file>` —— 🔴 该数**引用前必须当轮重测**，它会随对方每轮改动变动）。
2. 取**被监视源文件的 md5 基线**（打算改的 `.js` / `.py` / 门脚本）——本环结束时用同一批 md5 证明"读数属于这棵树"。
3. 若暂停/恢复过：核实没有别人已经改过你要动的那几行；拿不准先只读不写。
4. 🔴 并行会话安全（共享树纪律）：**禁 `cp` 整文件恢复**（曾覆盖并行会话的新版）、禁 `git checkout --` 恢复自己未提交的改动、禁在共享树上 `git stash`；恢复一律用 `/tmp` 备份 + 按行回退。

## 2. 实现硬约束（写代码时同时守住，别等验收再补）

- 单层弹窗：任意交互序列后 `.modal-mask` 计数 ∈ {0,1}（规矩 16，**方案阶段就查**）。
- 三态位不许折叠成两态：只认 `=== true`（`null` = 未落库）；判据/开关对象必须与需求那个集合一致。
- 颜色只走 CSS 令牌；数值口径用现行四词（厂商 / 供应商 / 资源 / 网关模型）+ 供应商模型名（`mg-terminology`）。
- 判据单一主人：同一个语义只允许一处判定；界面不得自建"进不进池"之类判断。
- 修缺陷**禁止回避式**（Q35-③ 红线）：成员/通道收不下时在根因处整形或在我方适配层吸收，**不许**用"跳过它/隐藏它/让门变绿"交付。
- 零垃圾（规矩 12）：临时探针/副本一律 `/tmp`，跑完清理；仓库内新脚本只能进 `bianyiandhuanjing/scripts/` 且带元数据头。

## 2.5 UI 量测与取证姿势（改 UI 前后必查 · 2026-10-11 收编 P6 精华；本节=唯一主人，教训正文在 pitfalls 只留编号）

- 布局判据**成对**：对齐（同列右缘差 ≤0.5px）+ 不溢出（零裁剪）；只验一侧 = 给自己发通行证（P-041）。
- 量**文本**不量盒子：`document.createRange()` + `selectNodeContents` 取文本矩形；盒子被 grid 拉满时量到的是 gap（P-040）。
- 画面证据把视口拉到目标元素之下再截/印（内部滚动容器 `scrollHeight` 恒等于视口高 ⇒ 要验的那屏根本不在版面内），readout 留「整表进画面=true」自证列（P-084）。
- 画面异常先查环境再谈判据：0 宽视口把 `vw` 钳成 0（P-028）、窗口 minimized 截图必挂（P-010）、中途 kill 毒化标签页（P-063）——修环境重跑，不算判据红。
- 几何/DOM 读数一律先在 `page.evaluate` 取成变量再喂判据；改完门先做内嵌 JS 抽取检查（runbook §3.0 + `mgw-gate-hygiene` §2）。
- 现成探针：`bianyiandhuanjing/scripts/probe_trend_charts_geometry.py`（趋势图柱体 0px 事故后立）与 `probe_*.py` 探针族（清单见 `mgw-live-audit` §1）。

## 3. 阶梯验收（顺序不可跳，命令见 runbook §3）

1. **ES 模块语法**：改过的每个前端 `.js` 都 `cp x.js /tmp/x.mjs && node --check /tmp/x.mjs`（🔴 `.js` 直查 = 假绿；正文与命令唯一主人在 runbook §3.0，事故实例 = pitfalls P-033）。
2. **全量机械门**：`ship-gate.sh --gates`。🔴 `[1/2]` pytest 非 0 → 脚本**直接 exit、`[2/2]` 根本没跑**；这时必须手工复跑其它门，才能报"其余门号"。
3. **逐门取终局行**：一律 **grep 关键词**（`合计：` / `可红` / `实测 `），**不许 tail**——失败清单打在合计行之后。
4. **真机门**：`verify_accounts_ui_live.py --port 84xx`（隔离实例 + 假上游；端口 8400–8499）。`--skip-legs` 是调试开关、**不得作交付口径**；若因"额度联网腿会真实出站且未获批准"而跳过，必须写明"本轮未交付全腿+登记未跑腿"。跑前=跑后源码 md5 一致，否则该轮读数作废。
5. **取证分级**：只读探针 / DOM 读数 / 几何读数是证据；**注释里的断言不是**；无画面时如实写"无画面证据"。
6. 任何一条红 → 先归因再修：门自己坏 / 判据过期 / 实现缺陷三类分开（流程见 skill `mgw-gate-hygiene`）。

## 4. 双向撤证（每处改动一条）

对每处**可被门观测**的改动：退回坏形态 → 跑门 → **红在该红的那一条**（报名字，不只报计数）→ 复原 → 与基线 md5 逐字节一致。
🔴 配方（`.pyc` 等长替换 / 串行独占 / 清 `__pycache__`）**抄 skill `mgw-gate-hygiene` §5**，本文件不复制。
不可被任何门观测的改动（纯文案等）：**如实标"未验证"**，不要为凑红证造场景。

## 5. 计数与台账收敛（一次改完，别开第 N 轮）

2. 岛式取值：`git archive HEAD` 解到 `/tmp` → 在 `coding/` 用主仓 venv 跑全量 → README 取「收集数 − skip 数」；**收集面含 `coding/tests/` 下五支 `verify_v*_repro.py`**（`coding/pyproject.toml` 的 `python_files` 覆写；行号随编辑漂移不引，事实以该键现值为准）。
2. 双语 README 两处同改：badge + 正文（zh-CN 同步）。守卫窗口是**单向区间** `[collected−20, collected]`——不许虚报。
3. 🔴 本机守卫因"并行会话未跟踪测试"而红是**设计内**：报备 + 写明红因 + 登记债务，**禁改数字蒙绿**（`pitfalls.md` P-066）。
4. 台账落在 `docs/changes/e2e-records/E2E-YYYYMMDD-<主题>.md`，固定段：§0 用户原话 → §改动面/根因（实测）→ §判据（随设计前进，不删条目）→ §撤证 → §门行（抄运行器原话 + 原文路径）→ §未做/未验（如实）→ §归案。
5. `docs/` 被 gitignore ⇒ 台账**永不进提交**；这不是失败，别为它改名换目录。

## 6. 归案（四件套，能少不能漏）

- `docs/specs/*`：改了行为/契约 ⇒ 对应 spec 升版；**版本号取下一个空位**（落笔前 grep 现值；被并行会话占了就顺位，并在正文写明改号原因）。
- `AGENTS.md`：状态链补本轮一行（证据路径 + 门行数字）。
- `.cursor/memory/`：新坑 → `pitfalls.md` 一行（现象/根因/修复方向/日期）；关键"为什么"→ `decisions.md`；新命令 → `runbook.md`。
- 用户级 skill 的规则若有变化（如本环流程本身）→ 更新对应 SKILL.md。

## 7. 上线判定（最容易撒谎的一步）

| 改动面 | 生效方式 | 判据 |
|---|---|---|
| 纯前端 | `no-store`，**刷新即生效** | 供出的静态资源 md5 == 磁盘 md5 |
| 含后端 / 配置语义 | **必须重启 `:8300`**，且**未重启不算交付** | ① 幂等零写盘请求的回执出现**新键**；② `coding/data/config.yaml` 跑前=跑后 md5 一致；③ `/openapi.json` 路径数含新端点 |

🔴 重启走 `os.execv` ⇒ **同 PID**：`ps` / `ps -o lstart` **不变**，进程时刻**不是**重启判据。重启/停止**须用户逐次批准**。
若无法只读证明（例如唯一能证的 POST 会真写盘）⇒ 判 **"未上线"** 并报备分裂状态（新前端 + 旧后端）及其风险，不许写"已生效"。

## 8. 交付话术（固定形态）

一句话结论 + 门行数字（抄运行器原话）+ 改动文件清单 + **显式"未验证"清单**（每条写缺什么前置、为什么代理证据不算）。发现自己的上轮结论有错 → 开头立"更正声明"，逐条列原说法与更正依据。

## 9. 红线清单（违反即停手）

- 真实厂商出站 / 写真实 `coding/data/config.yaml` / 重启 `:8300` / `git push`：**先获用户批准**（规矩 13；runbook §5）。
- 无证据写"完成/已跑通" = 违规（铁律 2 / 规矩 4）。
- 不得放宽判据、不得删判据条目、不得空过（空判据 = 没断言）。
- 同一问题第 2 次未解决 → 停手书面升层（规矩 8），禁止原地打补丁。
