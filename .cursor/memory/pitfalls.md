## 前端 / 浏览器
- **P-002** grid 扁平单元格结构（无行包裹 div）下，行内绑定若用 `closest("[data-行]")` 取索引，必须给**每个格子**都补行标属性（漏一个 → closest 返回 null → `Cannot read properties of null (reading 'dataset')`，且中断同批后续绑定）；组合行索引（全局 i）与分段索引（i - 已存数）要区分，用错即静默越界 undefined（async 处理器表现为「点了没反应」，错误走 unhandledrejection 不走 error 事件）（2026-09-05，模型列表草稿行检测按钮两连坑）

## 调度 / 重试 / 切换
- **P-020** **「避开/跳过」类判据必须配一条可达性对照**（2026-10-03 真厂商复验号级承载时定版）：观测到"资源 A 被避开、资源 B 承接"时，这个读数与"A 根本没进池（停用 / 无凭据 / 不可达）"**完全同形**，单看它证明不了任何避开逻辑。对照做法 = 把唯一的自变量改掉再打一次（本轮：同一条请求只把 `max_tokens` 从 4096 降到 128 ⇒ 那个号**照样被派到并成功**），才能把红/绿归因到判据本身。**同一逻辑的写侧版本**：回执里"部分成功"与"整条被拒"必须用**权威字段**区分（本轮 = `product_models` 里有没有这一条），不许解析人类文案 —— 文案会改，字段是契约（后端两种成因的逐字措辞本来就写着差异，`skipped` 有两种语义就是这条坑的源头）。锚：台账 `E2E-20261002-q33-multiaccount-parallel-spec.md` §15.4 / §16.1；判据 INT-94 第③条（作用域对照）与 `verify_map_switch_receipt.mjs` A1/A2/A3。 ⇒ 派复验角色时，"每条避开/跳过类结论都要带对照腿"要写进它的硬纪律。

- **P-024** 2026-10-04（同轮续做）**打带思考的模型做探针，`max_tokens` 给小了会产出「success + 正文为空」**：`hy3` 在 `max_tokens=256` 下 256 个 token 全花在推理上（`completion_tokens_details.reasoning_tokens=256`）⇒ 正文空串，事件行却是 `success`、上游正常给完了预算内的流。这不是通道故障，是**我预算给小了**（与「空返回 ≠ 通道不可用」「流式只取首帧即止 = `aborted`」同族，一天里第三次）。规矩：对设有思考档位的产品探针一律给 ≥2048 的输出预算，判成不成功要同时看 `content` 与 `reasoning_tokens` —— 只看正文为空就当通道坏了，会把健康号误判成不可用。

## 概念归属（厂商 / 供应商 / 网关模型 / 资源）—— 2026-10-04 概念审计轮
- **P-074** 🔴 **同一个"词表"可能有三层主人，混用必出真故障**：推理档位有 ① 网关规范七档 `dialects.LEVELS`（+ `CLOSED_LEVELS`/`is_closed`，`caps.thinkingLevelMap` 的键就是它），② 厂商在册档（内置目录 `EnumEntry.effort_levels`），③ 该供应商通道的参数名/合法性。本轮抓到两条 P0 全因把①当成②：`ir.merge_reasoning` 只认字面 `none` ⇒ 工具按网关自己发布的 `off` 关推理，被判成"开启"再升到厂商最高档；`degrade_effort` 把规范外词当"高于 max"取 `len(LEVELS)` 当下标 ⇒ `degrade_effort('none',['low','high'])` **IndexError = 正常请求 500**。规矩：**关闭语义只有一份词表（`is_closed`），关闭档不参与就近升降**；查档位表第二级必须带**本次请求的网关模型**，不能用"这条资源挂到的第一个网关模型"（别名形状下会拿别家厂商的表降档，答案随 `models[]` 书写顺序翻转）。
- **P-075** 🔴 **网关注入的默认值不许当"客户端的要求"反过头拦资源**：`_capacity_reject` 读的是注入后的 body ⇒ 初始化映射灌进 `params` 的厂商 `max_tokens:65536` 被当成"这次请求要 65536"，与按号 48000 一比就把号判超窗，客户端一个字没写却 0 出站 / 503。承载校验的依据只能是**原始请求里显式存在的量**。
- **P-076** 🔴 **同名字段两种主人**：`Resource.vendor`=供应商展示名、`EnumEntry.vendor`/`ModelInfo.vendor`=厂商；`Resource.account` 只是**可选备注**、`account_ref` 才是身份。熔断/统计/join 一旦用 `account` 或让备注进计数键，就会出现"该熔的照常被派活、不该熔的被误熔"和"1 家供应商数出 4 个"。判身份看它在哪一层、join 只用必填身份字段。
