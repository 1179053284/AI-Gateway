## ⑥ 拒跑轮的可读性（只判不改码）

原文（`model_gateway/ops/runner.py:426-432`，每个账号一条 `OpResult(a, "failed", why)`）：
> 运营互斥锁目录不可写：`{lock_dir}` —— 跨进程互斥建立不起来，本轮未对任何账号发起操作（宁可拒跑也不双领）。请检查数据目录权限或是否被只读挂载

CLI 抬头（`model_gateway/cli_zcode.py:285`）：
> `✗ 失败 3 个：` 然后逐行 `    {账号名}  {上面那整句}`（同句重复 N 遍）

判定：**会被读成"领了但失败"**，四个叠加原因：
1. 分类词「失败」在本文件的既读语义是"对上游发起过领取但有错"（同屏还有 `✓ 已领取`/`– 跳过`，
   三者构成"发起了"的动词序列）；"未发起"这个关键信息被压在抬头之下、长句**中段**，
   而抬头是唯一被扫读的行。
2. 同一账号级长句重复 N 遍 → 视觉上正是 N 个**独立**账号各自失败，强化"逐个领失败了"的读感；
   真实结论恰恰是"一个都没试"。
3. 用户可做的错误处置已被触发：换凭据/重新 `mgw zcode login`（抬头说失败），
   而真因是目录权限/只读挂载。句尾「请检查数据目录权限」离抬头太远、且被账号名分行隔断。
4. 退出码 1 与真失败同码（熔断才有 3），脚本/CI 读不出"未发起"。

改写建议（不动代码结构，仅文案；保留走 `failed` 通道以让红点/落盘/非 0 退出成立）：
- **抬头分级**：当 `report.failed` 的 reason 全部是同一条拒跑因由时，抬头改印
  `✗ 本轮拒跑：未对任何账号发起领取（3 个账号未开始，非领取失败）`；
  明细行只印一次成因，账号列表压到最后一行 `    未发起账号：a / b / c`。
- **reason 首句前置结论**：`未发起（本轮拒跑）—— 运营互斥锁目录不可写：{dir}；
  跨进程互斥建立不起来，宁可拒跑也不双领。` + 独立一行 `  处置：检查该目录权限或是否只读挂载，
  恢复后重跑 mgw zcode claim（本轮未领取任何额度，无重复领取风险）`。
  「未发起」放在第一个词，直接对冲抬头的"失败"读感；「无重复领取风险」回答用户此刻真正的担心。
- **退出码**：拒跑建议单独一级（如 4）并在 §21.3/README 的退出码表登记，让脚本能区分
  "跑了但有错"与"根本没跑"（这条属 PM 域，标为建议）。
