## 0. 结论先行

### 0.1 用户三项意图的直达答案

1. **DSH 插件「怎么接入不同产品 + 同产品多账号」**：11 个 provider 实例 / 7 个平行类型（`20 §1.1`），范式 = 「一产品一 `*-product.ts` 平行接口 + 两步式登录收敛 + 凭据/索引分离 + 账号池三步过滤」，但账号池**无并发租约**（旧缺口未修且新增两处同型缺口，`20 §2.5`）；同产品多账号靠「每账号一套凭据 + 每账号设备标识」，**仍无跨账号设备唯一性校验**（`20 §2.7`）。
2. **DSH「怎么读产品内部模型给 dsh 用」**：逐产品模型清单来源成表（远端探测/磁盘缓存/恒本地表/静态白名单四型，`21 §1.1`）→ 适配器自播报能力位（未知不编造）→ 宿主内 `AsyncIterable` 契约消费；**对外输出面为零**（无端口、无 OpenAI 端点、无反向编码器）——**网关正确姿势不是"接插件"，而是抄协议情报直连上游**（`21 §3.5`，三条路径已判定）。
3. **ZCode-Panel「买外部账号登录信息给本机登录」+ Z-Accounts-Gateway「简易网关」**：ZCode-Panel 的「买号」= 外链小店 + **人工粘贴导入**（无购买实现、无窄桥；`22 §④`）；「导入→本机可用」链路 = 导入写账号目录（credentials+config+meta+deviceMid）→ 切换 = `.current` + 杀进程 + 换数据根重启（`22 §⑥/§⑦`）；两条硬边界：**跨机 `enc:v1` 密文必失败**、「只校验 UUID 格式、不查跨账号唯一性」现版本**仍未修**（`22 §5.6`，我们 Q27-⑤ 补偿项有效）。Z-Accounts-Gateway 的 gateway-core = 6 端点 + 常数时间鉴权 + 双向协议翻译 + 只读快照 + 最少在途/LRU（`23 §2`），**最重的两条**在其注释里：① 直连 `zcode.z.ai` 即使带合法验证码参数也被 405/3012 拦（作者 2026-09-26 自述验证）② 验证码须在官方渲染器内 CDP mint（`23 B10/N8`；主会话已直接读源码复核，见 §5）。

### 0.2 相对既有调研的增量

- **DSH 插件**：6→11 provider、4→7 类型、RPC 16→26、新机制 6 项（`expiry-sync` / `permanent-lock-store` / `jet-hub-store` / 余额分档选号 / 永久积分锁 / 精确等待）；**3 条旧结论失效**（含 1 条「直接抄」作废，`20 §0.1`）。
- **ZCode-Panel**：`import-account.js` 整文件重写（双家族 + 写回自检回滚）、`main.js` 行号 +33~+61 漂移、渠道 B「浏览器授权导入」与 D「外部凭据导入」补全、`deriveSigningKey` 休眠能力新发现（`22 §⑧`）。
- **Z-Accounts-Gateway**：全新材料、零既往覆盖（`23`）。

### 0.3 本轮产出的下一个动作

四个待裁决点（§2）→ 用户裁决 → 需要改定论的按惯例开新 Q 号回写 PRD/tech-design；其余吸收项在对应里程碑实施时并入其验收判据。
