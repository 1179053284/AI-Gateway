## 1. 总则

### 1.1 技术形态（tech-design §4.9 宪法级约束）

- **无构建**：原生 ES Modules + 手写 CSS；`model_gateway/web/static/` 内置，FastAPI StaticFiles 挂载 `/`
- **静态资源禁缓存（Q19-①，2026-09-05 加严）**：`main.py` `_StaticNoCacheMiddleware` 给全部静态资源（HTML/JS/CSS）加 `Cache-Control: no-store`（原 no-cache——本地静态资源无缓存价值，no-store 不落盘更彻底）——**杜绝浏览器缓存新旧混载的 ES 模块导致 import 失败**（实测症状：框架在、内容区永久空白）；另 `index.html` 装载兜底：3s 未见到 main.js 启动标记则在内容区显示「强制刷新」指引；API 响应不受影响
- **图表**：vendored 本地 Chart.js（MIT，随仓库内置）；**禁止任何 CDN**
- **数据流**：全部操作走 `/admin/api/*`，最终读写 `config.yaml` / `model-enums.yaml`（界面与文件双向一致——文件外部修改经 1s mtime 轮询热重载生效，界面刷新即见）
- **鉴权（本轮修正 ①）**：管理界面**免鉴权**——无令牌门、无 Authorization 头，`/admin/api/*` 本机直访（自用系统，绑定 127.0.0.1/LAN 仅可信内网）；仅 `/v1/*` 业务端点保留访问令牌校验（令牌在 API 接入页管理，见 §2.4）

### 1.4 扩展性设计原则（为未来接入不同厂商、各类 Plan、数据统计与展示预留）

1. **厂商中立**：界面元素（资源表格列 / 向导 / 统计维度）全部由配置与预设数据驱动渲染，**无厂商专属硬编码分支**；厂商差异只存在于预设模板数据与协议适配器——新增厂商 = 新增预设 + 协议适配器，前端零改动
2. **预设注册表驱定向导**：「新增资源」向导的预设下拉数据来自 `GET /admin/api/presets`（内置 sensenova-api 商汤按量 / sensenova-tokenplan 商汤 TokenPlan / custom 空白模板，见 §3），选中预设自动填充接入模式 / 协议 / base_url / 说明文案
3. **Plan 类型 / 计费口径可扩展**：`access_mode`（api/plan）随预设带入可改；界面遇未知口径优雅降级显示「—」，不报错不隐藏
4. **统计维度数据驱动**：看板维度 tab 由 `/admin/api/stats` 返回的维度键（by_model / by_resource / by_token / by_provider / by_account）数据驱动生成，前端不写死维度清单——后端新增维度，界面自动出现对应 tab
5. **前端页面注册表**：`main.js` 维护页面模块注册表，新页面 = 注册一个 page 模块（标题 + 图标 + 渲染函数），侧导航与 hash 路由自动生成
6. **基础组件参数化复用**：表格 / 表单 / 弹窗 / 无边框 tab / toast 等通用组件集中于 `components.js` 参数化复用，**禁止页面间复制组件结构**
