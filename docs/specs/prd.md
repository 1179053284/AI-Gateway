## 1. 产品概述

### 1.1 定位
面向**个人开发者**的本地 LLM 网关（模型聚合网关）：将**多厂商、同厂商多账号多 Key** 的模型权益（含各家活动资源/免费额度/订阅套餐）汇总接入，构建**自己的模型资源池**；对外暴露**统一 API**，供本地及局域网内 AI 开发工具（Trae / Cursor / Cherry Studio / Claude Code 等）调用。

### 1.2 核心价值
1. **聚合资源池**：一处配置全部厂商资源（厂商 + Key）与模型映射，工具端只连网关一个地址。
2. **可靠**：失败自动重试（m 次）与资源切换续跑（同模型多资源池），调用不因单 Key/单厂商故障中断——有可用资源即不向工具端报错；冷却后自动恢复；工具中断调用可透传取消上游。
3. **可视**：接入信息统一管理（资源列表 + API 接入指引）+ 统一模型名自动匹配 + 调用量/token/费用多维度统计与健康看板。

### 1.3 设计原则（宪法级约束）
- **全明文**：配置与统计数据全部本地明文文件（YAML / JSON / JSONL），可读可改可备份。
- **纯本地**：无遥测、无远程配置、无自动更新、无任何远端依赖；局域网监听仅服务用户自己的设备。
- **密钥本地**：厂商凭据（API Key / 订阅 Token）仅存本地明文配置（或环境变量引用），不入 git、不硬编码进源码。
- **单用户**：无多用户/注册/登录体系；网关 `/v1/*` 调用以访问令牌（access token）保护，**管理界面与 `/admin/api/*` 免鉴权**（本机自用，Q18-①）。

### 1.4 已确认的关键需求决策（2026-09-02 用户确认）
| 决策点 | 结论 |
|---|---|
| 协议范围（P0） | **三大协议全支持**（出站适配）：OpenAI 兼容 + Anthropic 原生 + Google Gemini 原生 |
| 接入模式（P0） | **两大类接入方式**：**API 模式**（普通按量 API Key）与 **Plan 模式**（TokenPlan / CodingPlan 等订阅套餐）；接入时必须选择，**配置信息不同**；同一厂商可同时存在两种模式接入 |
| 首发厂商（P0） | **商汤科技 SenseNova 优先接入**：按量 API（`https://api.sensenova.cn/compatible-mode/v2`）与 TokenPlan（`https://token.sensenova.cn/v1`）**两预设均内置**，实际接入端点以 M1 首项**双端点实测**定论（Key 体系归属见 §9-Q12，核实口径见 §9-附注）；模型清单以接入后 `GET /models` 实测为准 |
| 请求级重试与切换续跑（P0 · 2026-09-02 新增） | 网关调用厂商失败 → 同资源自动重试，上限 **m 次**（**m 默认 3**，可配）；重试耗尽 → 自动切换到下一个同模型的可用资源**重新调用并继续执行任务**；**只要有可用资源，不中断、不给工具端报错**。失败判定按**厂商资源维度**计数，命中条件即更换资源 |
| 流式中途失败策略（P0 · 2026-09-02 确认） | **首 token 输出前**失败：重试 + 换资源续跑（工具端无感）。**已输出部分内容后**失败：依据厂商明确错误码，可重试的（稳定性类错误）按规则重试；不可重试/不确定的：**把已收到的厂商输出与错误信息原封透传给工具端**，由用户判断是否重新触发（不吞内容、不无感重放） |
| 生效集分流策略（2026-09-03 重对齐） | **并发溢出生效集，不轮询**：生效集 = top-x 可用资源；请求打到生效集内**在途请求最少**的资源（平局取优先级高者）——低负载顺序集中打最高优先级，并发时溢出到生效集内下一资源（**最多 x 个资源同时承接流量**）；失败即移出、由下一个可用资源补位（Q13） |
| 并发的含义 | 并发指**多个 AI 工具同时调用网关**须稳定；**厂商侧资源并发不做管理** |
| 监听与鉴权 | 监听全部网卡，**本机地址与局域网地址两种调用方式都要支持**；`/v1/*` 调用**均需访问令牌**；管理界面与 `/admin/api/*` **免鉴权**（本机自用，2026-09-03 Q18-① 修订，推翻 Q16-1 管理鉴权结论） |
| 补充功能取舍 | 冷却自动恢复、请求日志页、网关访问令牌、成本估算——**全部纳入 P0** |
| 终止转发（P0） | 工具内终止模型调用时，网关**透传取消上游请求**；客户端主动中断不计失败、不触发切换 |
| 统一模型名（P0） | **公共枚举池**：内置主流模型规范名清单 + 别名；录入时自动匹配推荐统一名，可手动修改；支持自定义扩展 |
| 图像生成模型（P0 · 2026-09-02 确认） | 商汤 U1.5 Lite / U1 Fast **首版就要支持**：独立 images 端点（`/v1/images/generations`），配置为「图像生成」分组系统模型；不入 chat 资源池 |
| Plan 额度感知（2026-09-02 确认） | **暂不做**：本期商汤仅接按量 API；待后续接入 plan 模式厂商时再议 |
| 信息核实纪律（2026-09-02 确认） | 外部资料仅采信**官方文档**（用户指定资料）与 **GitHub 实际项目代码**；搜索引擎二手内容（博客/营销页/AI 生成文）不作为依据 |
| 推理参数（2026-09-03 确认，Q15） | 网关调用支持**推理开启与强度设定**；**资源级默认 + 请求级覆盖**——调用接口时指定则接口值生效，未指定走该资源配置的默认推理参数，资源未配置则不注入（走厂商默认）；切换续跑时按目标资源默认重新合并（FR-3.16） |

## 2. 术语与核心概念

| 术语 | 定义 |
|------|------|
| 厂商 Provider | 模型服务品牌（商汤、DeepSeek、Anthropic、Google、OpenRouter…），含自定义 base_url 的兼容端点；由**厂商预设**（preset）标识与预填 |
| **接入模式 Access Mode** | 资源接入的两大类：`api`（普通按量 API Key）与 `plan`（订阅套餐：TokenPlan / CodingPlan 等，积分/额度制，常含滚动周期额度与专用 base_url） |
| **资源 Resource** | **厂商 + Key** 的扁平接入单元（Q18-②），系统自动生成全局唯一 ID（`res-xxxxxxxx`）；可关联**账号备注**（`account`，次要信息，用于区分/识别同厂商不同账号）与名称备注（`name`）；是接入管理与统计的核心对象 |
| 账号备注 Account | 资源的可选次要字段，标注该 Key 归属哪个账号（如「主账号」「活动账号」），仅用于区分与统计，**不构成管理层级**（Q18-② 推翻「接入实例→账号→Key 三层管理」） |
| 厂商模型 Vendor Model | 厂商侧的模型 ID（如 `sensenova-6.8-flash-lite`），录入时系统自动匹配统一名 |
| 统一模型名枚举池 Model Enum | 内置规范模型名清单（含别名/分组）：主流模型全收录，可扩展；用于自动匹配与手动纠错 |
| **映射条目 Model-Resource Entry** | 系统模型资源池中的一项：**资源 ID + 厂商模型 ID**（+ 可选资源级推理默认）；调度最小单元，拥有优先级（池内顺序）、状态、失败计数 |
| 系统模型 System Model | 网关对外暴露的统一模型名（取自枚举池或自定义），供工具端调用 |
| 资源池 Pool | 映射到同一系统模型的全部资源（有序，按优先级排列） |
| 生效集 Active Set | 某系统模型当前激活的资源集合（≤ x 个，成员被移出时由待命资源补位）；请求打到集内**在途请求最少**的资源（平局取优先级高）——低负载集中、并发溢出（Q13） |
| 切换 Failover | 生效资源因故障被移出生效集（进入冷却），由待命资源补位的过程 |
| **重试 Retry** | 网关调用厂商失败后，在**同一资源**上重新发起；单次请求重试上限 **m 次**（全局可配，Q18-④ 取消按模型覆盖） |
| **切换续跑 Failover-Continue** | 重试耗尽后，当次请求自动切换到**下一个可用资源**重新调用并继续执行任务（对工具端透明） |
| 冷却 Cooldown | 资源被移出后静置 N 秒，期满自动恢复进入可用范围 |
| 取消透传 Cancel-Propagation | 工具端中断请求 → 网关检测并主动断开对应的厂商上游请求 |
| 访问令牌 Access Token | 客户端工具调用网关 `/v1/*` 所需的鉴权凭据（多个、可命名区分工具、可启用/停用/删除）；在 **API 接入页**统一管理（Q18-③） |

## 3. 总体形态（建议，技术方案实施前评审）

- **单进程本地服务**，同时提供：
  - **统一 API（入站）**：OpenAI 兼容端点为主（`/v1/models`、`/v1/chat/completions`、`/v1/images/generations`）+ Anthropic 原生端点（`/v1/messages`）；Gemini 原生入站端点列 P2。
  - **Web 管理界面**：浏览器访问。
- **出站适配**：三大协议族适配器（OpenAI 兼容 / Anthropic / Gemini），统一转换为内部标准消息格式后调度。
- **监听与调用地址**：监听 `0.0.0.0:<port>`（默认 8300，可配）；界面同时展示两种调用地址——本机 `http://127.0.0.1:8300/v1` 与局域网 `http://<局域网IP>:8300/v1`；两种地址调用均需访问令牌。
- 技术栈建议：Python 3.12+ / FastAPI（异步 + SSE 流式）+ httpx（厂商请求）+ uvicorn；Web 界面轻量无构建方案——最终以技术方案评审为准，不在此锁定。
- 数据落盘（全明文）：
  ```
  data/
  ├── config.yaml          # 资源（厂商+Key）/模型映射/网关与调度参数/访问令牌/单价表
  ├── model-enums.yaml     # 统一模型名枚举池（内置清单 + 用户扩展/纠错记录）
  ├── gateway.lock         # 单实例锁（明文 JSON：pid/port/base_url/started_at；运行期存在，正常退出释放，FR-12.3）
  ├── usage/
  │   ├── events-YYYYMM.jsonl         # 调用事件流水（追加）
  │   ├── switch-events-YYYYMM.jsonl  # 重试/切换事件流水（追加；供请求日志页与 AI 排查直查）
  │   └── daily-YYYYMM.json           # 日聚合快照（供看板查询）
  └── logs/                # 运行日志（gateway.log，key 脱敏）
  ```

## 4. 功能需求

> 优先级：P0 = 首版必须；P1 = 首版后尽快；P2 = 可选增强。

### FR-1 资源管理（P0 · Q18-② 扁平化重整）
> **架构定论（2026-09-03 Q18-②）**：资源 = **厂商 + Key**，扁平一层管理；**推翻** v1.0「接入实例（Provider Instance）→ 账号 → Key」三层结构——原因：系统重点是**厂商资源**本身，账号仅是「区分、备注、识别是哪个账号下的」**次要信息**，不值得为其建立管理层级；三层嵌套导致界面层级深、操作繁琐、信息不直观。厂商维度由**厂商预设**（preset）承载，统计维度由事件行冗余 `provider` / `account` 字段承载（FR-6.1），管理对象收敛为**资源列表**。
1. **资源管理（P0 · 扁平模型）**：
   - 新增资源时选择**厂商预设**（预设自动填充协议/base_url/接入模式等模板信息）或 `custom` 空白自定义；填写名称、API Key、可选**账号备注**（区分同厂商不同账号，次要信息）；
   - **资源 ID 系统自动生成**（全局唯一 `res-xxxxxxxx`，Q18-②：ID 属于系统内部标识，用户不关心、不需要手填）；新建时 ID 留空由服务端补齐；
   - 同一厂商可添加任意多个资源（同厂商多账号多 Key 天然支持——每个 Key 一条资源，各自标注账号备注）；
   - **资源字段**：`id`（自动生成）/ `name`（名称备注）/ `preset`（厂商预设，custom 则空）/ `access_mode`（`api` | `plan`，随预设带入可改）/ `protocol`（`openai` / `anthropic` / `gemini`）/ `base_url` / `api_key`（明文，界面脱敏显示）/ `account`（账号备注，可选）/ `enabled`（停用开关）；
   - **Plan 模式差异**：预设含套餐类型标注（如 TokenPlan / CodingPlan）、计费口径（积分制/订阅内不计费）、额度周期说明（如商汤：滚动 5 小时 + 滚动周两层额度）——仅作配置项展示，额度感知暂不做（见 FR-1.9）。
2. **内置厂商预设（P0，首发：商汤）**：
   | 预设 | 模式 | 协议 | base_url | 说明 |
   |---|---|---|---|---|
   | **商汤 SenseNova API（按量）· 本期首发** | api | openai 兼容 | `https://api.sensenova.cn/compatible-mode/v2` | 按量付费 API，OpenAI 全端点兼容（chat/multimodal 均此端点）；Key 为 ModelStudio API Key（console.sensecore.cn 创建）；**模型清单以 `GET /models` 实测为准**（见 §9-附注） |
   | 商汤 SenseNova TokenPlan（本期不接入，预留预设） | plan | openai 兼容 | `https://token.sensenova.cn/v1` | 积分制（通用+专属积分、滚动 5h/周额度）；另有 Anthropic 兼容端点 `https://token.sensenova.cn`（SDK 自动拼 `/v1/messages`，不能带 `/v1` 后缀）；`sk-` 密钥（platform.sensenova.cn 控制台） |
   | 其余厂商预设（DeepSeek / Kimi / 智谱 / 通义 / OpenRouter / SiliconFlow / 火山引擎） | 按各家 | — | — | P1 逐个补入；预设仅提供接入模板，不产生任何远程同步 |

   **预设注册表与扩展性（2026-09-03 确认，Q17）**：预设以内置注册表形式提供（`model_gateway/config/presets.py`），每条字段：`id` / 名称 / 接入模式（`api`|`plan`）/ 协议 / base_url / 计费口径 / 说明文案；另含 `custom` 空白自定义模板；`GET /admin/api/presets`（管理端免鉴权，Q18-①）返回预设列表供资源表单渲染。**新增厂商或 Plan 类型 = 仅新增一条预设数据**（必要时新增协议适配器），资源表单与 UI 框架零改动；计费口径为可扩展枚举，未知口径优雅降级显示「—」。**预设不是管理层级**——仅是资源表单的模板数据源（Q18-⑤：系统设置页不再设「接入产品」管理）。

### FR-3 调度、重试与自动切换（P0 · 核心机制）
1. **资源池**：每个系统模型映射一个有序资源池（N 个资源，按优先级排列）。
2. **生效上限 x（2026-09-03 重对齐，Q13；2026-09-03 Q18-④ 定论全局唯一）**：一个系统模型**最多同时有 x 个资源承接流量**——低负载顺序集中打最高优先级资源，并发时溢出到生效集内下一资源（选路规则见 FR-3.3）。**x 为全局参数**（`scheduling.max_active_per_model`），对所有系统模型统一生效，**不支持按模型覆盖**（调度机制只有一套，Q18-④）；x=1 即纯顺序集中。
3. **并发溢出生效集（不轮询 · 2026-09-03 重对齐，Q13）**：每个请求打到生效集内**在途请求最少**的资源，平局取优先级高者。示例：资源池 [A, B, C, D]，x=2 → 生效集 {A, B}；**顺序请求全部走 A**（A 在途归零后新请求回 A）；**多工具并发时溢出到 B**（A、B 同时承接，任意时刻 ≤ x 个资源承接流量）；A 故障 → A 移出生效集并冷却，C 补位，生效集 {B, C}，流量集中/溢出于 B、C。
4. **请求级重试（P0 · 2026-09-02 新增；Q18-④ 全局唯一）**：网关调用厂商模型失败（可重试类错误，见错误分类表）→ 在**同一资源**上自动重新发起，最多 **m 次**（m 为全局参数，**默认 3**，不支持按模型覆盖，Q18-④）。重试间隔可配（默认 0 = 立即重试；429 类按官方建议采用**指数退避**）。请求内每次失败**同时累计**到该资源的连续失败计数（参与 y 判定）。
5. **切换续跑（P0 · 2026-09-02 新增 · 端到端不中断）**：单次请求在当前资源上重试耗尽（m 次）仍失败 → 系统自动切换到**下一个可用资源**（按 FR-3.3 同一选路规则取目标，排除本请求已尝试过的资源），用新资源**重新发起同一请求并继续执行任务**（仅针对当次失败的请求，不影响其它请求/会话）；新资源同样适用「重试 ≤ m 次 → 仍失败再切换」规则，如此往复，直到某资源成功或全部资源不可用。**只要还有可用资源，绝不向工具端返回错误**。
6. **流式边界与中途失败策略（P0 · 2026-09-02 确认）**：
   - **首 token 输出前**失败（绝大多数故障发生点）：重试 + 换资源续跑，工具端**无感**——主通道；
   - **已向工具端输出部分内容后**失败：网关**不无感重放**（重发会造成内容重复错乱），处理策略：
     a. 依据厂商**明确错误码**判断：属可重试类稳定性错误（网络中断/超时/5xx 等，且工具端支持重新发起时）→ 按错误分类表重试规则处理；
     b. 不可重试/无法判断的：**把已收到的厂商输出内容与错误信息原封透传给工具端**（SSE 按协议以 error/结束帧收尾），**不吞内容**，由用户判断是否重新触发让模型继续处理；
   - 依据：厂商有明确错误返回码（商汤错误码表见 FR-1.8）；正常情况下（非稳定性问题）厂商不会输出一半才报错，中途失败为小概率场景。
7. **失败阈值 y（资源故障判定）**：某资源**连续 y 次调用失败**（跨请求累计，含请求内重试计数）→ 判定故障，移出生效集进入冷却，触发待命资源补位。y 为全局参数（**默认 2**，不支持按模型覆盖，Q18-④）。
   - **m 与 y 的关系（2026-09-02 确认；生效顺序 2026-09-03 定论：y 先判定，Q14）**：m 管单次请求的重试上限（请求级，默认 3，重试耗尽即切换），y 管资源移出冷却的故障判定（资源级，默认 2，连续失败即切换）；**y 先执行判定**——默认参数下每资源每请求实际尝试 y=2 次即冷却 + 当次请求立即切换，m 的余量仅在 y > m+1 或 429 退避场景生效；失败判定按**厂商资源维度**计数，命中条件即更换资源；两参数独立可配、均为全局参数（Q18-④ 取消按模型覆盖）。
8. **触发切换/移出的条件**：
   - 可重试错误重试耗尽 → 当次请求切换续跑 + 累计失败计数（达 y 判定故障移出冷却）；
   - **厂商明确返回资源不足**（HTTP 429、配额/余额/积分不足错误码与错误信息，规则表可扩展）→ 先**短指数退避重试**（官方建议口径，如商汤 `quota_exceeded_error`；次数少、间隔短，默认 2 次），仍失败 → 立即移出 + 当次请求切换续跑。plan 模式下 429 常为滚动窗口额度耗尽（如商汤 5 小时窗口），冷却时长按接入模式单独配置（默认更长对齐滚动窗口；api 模式用全局默认冷却）。
9. **全部不可用兜底**：资源池内所有资源均不可用（含冷却中、重试与切换续跑全部耗尽）→ 才向调用方返回统一错误信息（各协议标准 error 格式，含「无可用资源」与原因摘要），禁止无限挂起。
10. **冷却自动恢复（P0）**：被移出的资源冷却 N 秒（可配，支持按模式区分默认值）后自动恢复进入可用范围（按原优先级归位）。
11. **取消透传（P0 · 终止转发）**：工具端中断调用（断连/停止生成）→ 网关检测后**主动取消并断开对应的厂商上游请求**（停止上游生成、止损）：
    - 流式：检测客户端断连后立即关闭/取消上游 httpx 请求；
    - 非流式：检测到客户端断连后取消仍在上游途中的请求；
    - **SSE 心跳**：上游长时间无数据时定时发送 keep-alive 注释块，尽早发现断连。
12. **取消语义（不计失败）**：客户端主动中断导致的半途请求**不计入失败计数、不触发切换、不影响冷却**；日志/统计中标记 `aborted`（含已产生的 token）。厂商侧返回 408 `canceled_error`（如商汤）同此语义。
13. **错误分类表**（调度依据；「请求级重试」指是否参与 FR-3.4 同资源重试；规则可配可扩展，厂商特殊语义由适配器校准——商汤实例见 FR-1.8 错误码表）：

    | 错误类型 | 请求级重试 | 失败计数 | 处理 |
    |---|---|---|---|
    | 网络错误 / 连接超时 / 5xx（商汤 `internal_server_error`） | 重试 ≤ m 次，耗尽后当次请求切新资源续跑 | 计入（达 y 移出冷却） | 请求内逐次累计 |
    | HTTP 429 / 配额、余额、积分不足（商汤 `quota_exceeded_error`，官方建议指数退避） | 短指数退避重试（默认 2 次） | 退避耗尽立即判定 | 移出 + 冷却（plan 模式冷却默认对齐滚动额度窗口，可配）+ 当次请求切换续跑 |
    | HTTP 401（Key 无效/鉴权失败） | 不重试 | 不计次 | 立即停用该资源 + 界面告警 + 当次请求切换续跑 |
    | HTTP 403（凭据/权限类；注意商汤 403 `permission_denied_error` = 不支持当前语言，属请求属性 → 透传不切换） | 不重试 | 不计次（凭据类） | 通用凭据类：停用 + 切换续跑；商汤语言类：透传调用方（适配器按错误 type 区分） |
    | HTTP 404（模型不存在/已下线，商汤 `not_found_error`） | 不重试 | — | 资源无效标记 + 告警（模型层面问题）+ 当次请求切换续跑 |
    | HTTP 408 / 厂商取消类（商汤 `canceled_error`） | — | 不计次、不切换 | 取消语义，标记 aborted |
    | HTTP 4xx 其它（400 参数错等，商汤 `invalid_request_error` / `failed_precondition_error` / `permission_denied_error` 语言类） | 不重试 | 不计数 | 错误透传给调用方（调用方请求本身的问题，换资源同样失败） |
    | 内容审核拦截（`finish_reason: content_filter`） | — | — | 正常结束，不算失败，不计切换 |
    | 客户端主动中断（取消透传） | — | 不计次、不切换 | 标记 aborted |

14. **切换与重试事件记录**：每次重试（资源、第几次、错误类型）与每次切换（时间、系统模型、从哪个资源 → 到哪个资源、原因）均记录落盘（`data/usage/switch-events-YYYYMM.jsonl`）；看板统计（切换/重试次数指标）与请求日志页「切换事件」tab 可查，排查可由 AI 直查明文文件（Q17）。
15. **超时与总预算（P1 · 2026-09-03 终审调小；Q18-④ 全局唯一）**：全局**单次尝试超时**默认 **60s**（原 120s，终审调小；思考型模型首字节慢若被误杀，实测后可调回；全局参数，不支持按模型/资源覆盖，Q18-④）；另有**请求总预算 300s**（单请求全部尝试+重试+退避的总时长上限，**不管成功任务本身的执行时长**——流式输出开始后不受限，耗尽即返回统一错误防挂起；语义详见技术方案 §5.5）。
16. **推理参数：开启与强度（P0 · 2026-09-03 确认，Q15）**：
    - 支持对支持推理的模型设定**推理开启**（thinking 开关，按厂商参数形态）与**推理强度**（`reasoning_effort`，取值以厂商为准，如商汤 V4 系 `low/high/max`，网关按 opaque 字符串透传不强校验枚举）；
    - **合并优先级**：**请求级（调用接口时指定）> 资源级默认（接入配置，按资源维度）> 厂商默认（不注入字段）**；请求方**显式关闭**同样优先于资源默认开启（区分「未指定」与「显式关闭」）；
    - **资源级默认**：同一系统模型下不同资源可配不同默认（如「免费活动资源默认 low 省额度、主力资源默认 max」）；仅 chat 类资源有效，images 类资源不适用（配置校验警告并忽略）；
    - **请求级**：OpenAI 兼容端点请求体中的 `reasoning_effort` / `thinking` 等字段原样透传（FR-5.1 既有原则），作为显式值参与合并；
    - **切换续跑**：换资源后按**新资源的默认**重新合并推理参数（每次尝试独立构造出站请求，FR-3.5 交互）；
    - 响应侧：思考内容按厂商流式字段差异归一化透传（`reasoning_content` / `thinking_content`，FR-1.8），不受本条影响。

### FR-4 多工具并发稳定运行（P0）
1. 全异步架构：**多个 AI 工具同时调用网关**互不阻塞；**流式（SSE）长连接不阻塞其它请求**；取消透传不阻塞其它连接。
2. 网关整体并发上限可配（保护本机资源，可选项）。
3. 稳定性验收：多工具并发混合场景（流式+非流式+中途取消）长时间运行无内存泄漏、无请求堆积（具体数值验收标准实施阶段定）。

### FR-5 统一 API（P0）
1. **OpenAI 兼容端点（主）**：
   - `GET /v1/models`：返回系统模型列表（OpenAI 格式，仅 enabled=true 的启用模型，FR-2.3）；
   - `POST /v1/chat/completions`：`stream: true/false` 全支持（SSE 逐 chunk 透传）；**工具调用（tool calls / function calling）透传**；请求体其余字段原样透传给厂商（含 `thinking` / `reasoning_effort` 等厂商扩展参数，推理参数按 FR-3.16 三级合并：请求指定优先、未指定走资源级默认）；配合 FR-3.10 取消透传。
2. **Anthropic 原生端点（P0）**：`/v1/messages`（含流式），供 Claude Code 等只认 Anthropic 格式的工具直连；内部同样走系统模型调度、重试与取消透传。
3. **图像生成端点（P0 · 首版支持）**：`POST /v1/images/generations`（OpenAI images 格式）：
   - `model` 填「图像生成」分组的系统模型名（如 `sensenova-u1-fast`）；请求参数（prompt、数量、尺寸/宽高比等）透传或映射至厂商端点；响应（b64/url 形式）透传返回；
   - 内部同样走系统模型调度、请求级重试与切换续跑、取消透传；
   - `/v1/images/edits`（图生图/编辑，U1.5 Lite 参考图能力）：P1。
4. Gemini 原生入站端点：P2。
5. **鉴权**：全部入站端点均要求访问令牌（`Authorization: Bearer <token>` 或 `x-api-key`，按各协议惯例）。
6. 错误响应统一为各协议对应的标准 error 格式。
7. **兼容性验收**：curl + 真实 AI 工具实测通过（首发以商汤按量 API 模型为实测对象，参考商汤官方工具接入指引：Trae / Cline / Claude Code / Cherry Studio 等），含中途停止场景的取消行为验证、**单资源连续失败自动切换续跑（工具端无感）**、图像生成调用。
8. 统计口径：流式请求的 token 统计优先读厂商 usage 字段（`stream_options.include_usage`，商汤各模型均支持），无则本地估算并标注口径；aborted 请求按已完成部分计入；图像生成请求计**调用次数与生成张数**（无 token 概念）。

### FR-6 调用量统计与数据看板（P0）
1. **统计维度**：
   - 网关维度（按**系统模型**）：调用次数、token 输入量、token 输出量；

   - 图像生成调用：调用次数、生成张数（无 token 概念，单独口径）。
2. **指标**：调用次数（成功/失败/客户端中断分别计）、token 输入/输出、**重试次数**、失败原因分布、切换次数、**平均耗时 / 首 token 时间（TTFT）**、**费用/积分估算**。
3. **成本估算（P0 · 双口径）**：
   - **API 模式**：按单价表估算费用（按厂商模型：输入/输出每百万 token 单价，图像生成按张单价；货币可配；厂商 `/models` 返回 pricing 元数据时可辅助预填）；
   - **Plan 模式**：按积分口径统计（积分系数可配，如商汤按模型积分扣减），或标记「订阅内不计费」；
   - 纯本地算术，非计费系统；未配置口径的模型不计费。
4. **时段与视图**：今日 / 近 7 天 / 近 30 天 / 自定义区间；天 / 周 / 月聚合；**日维度调用趋势图**；模型占比、资源占比等图表。
5. **存储**：本地明文（事件 JSONL 追加 + 日聚合 JSON 快照），看板查询聚合快照，不引入数据库。

### FR-12 系统运行控制（P0 · 2026-09-03 确认，Q17/D2-D4）

1. **界面重启/停止（P0）**：系统设置页提供「重启网关 / 停止网关」操作（**管理端免鉴权**，Q18-① 修订——原 v1.4 要求 admin 令牌 `allow_admin`，随管理鉴权整体移除而取消）：
   - `POST /admin/api/system/stop`：**优雅停机**——在途请求收尾后退出进程，并释放单实例锁（FR-12.3）；
   - `POST /admin/api/system/restart`：优雅停机 + 释放锁后，经 `os.execv` **进程映像替换自重启**（D3）——**PID 不变、同端口重绑、配置重读、锁重新登记**。
2. **双击启动脚本（P0）**：项目根提供 `启动网关.command`（macOS 双击启动，`chmod +x`）：
   - 脚本流程：cd 到脚本自身所在目录 → 检测 `.venv`（缺失时打印环境搭建指引、**窗口不关闭**）→ **前台启动网关**（日志可见、Ctrl+C 可停）；
   - 已有实例运行时：窗口显示已有实例的后台地址并保持窗口开启（不重复启动，联动 FR-12.3 检测）。
3. **单实例运行限制（P0 · 用户定论：暂不考虑多套并行，同一时刻仅允许一套实例运行）**：
   - 锁文件 `data/gateway.lock`，**明文 JSON**（可查可删，D2），字段：`pid` / `port` / `base_url`（后台地址）/ `started_at`（启动时间）；
   - 启动检测流程：锁不存在 → 写锁启动；锁中 pid 为**自身**（`execv` 重启场景）→ 覆盖重写锁后启动；锁中 pid **存活**（其它实例运行中）→ 打印「已有实例运行中：后台地址 `http://127.0.0.1:<port>/`（PID、启动时间）」并以**退出码 3** 退出——不启动、不换端口、不询问，交互/非交互行为一致（D4）；锁中 pid **已死**（陈旧锁）→ 自动清理后正常启动；
   - **锁释放**：正常退出（stop / restart / Ctrl+C / 信号）经 atexit + 信号处理释放锁；锁检测遗漏的极端场景由端口绑定失败兜底——明确报错退出，不静默换端口。
